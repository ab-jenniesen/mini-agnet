# V1.2 实现与配置指南

本文对应当前 `1.2.0` 开发代码。完整候选对象设计见 [对象草案](./runtime-object-model.md)；实际字段以 `src/core/execution/types.ts` 为准。

## 1. 本版执行流程

```text
创建或选择 Task
    ↓
创建独立 Run
    ↓
模型调用 submit_delivery_checklist 提交交付模式、文件清单和计划
    ↓
按配置确认计划，或直接执行
    ↓
运行默认 / 自定义执行工作流
    ↓
文件交付：检查实际文件；缺失时反馈并重新进入执行子图
纯回复：记录文件检查不适用
    ↓
保存结果、报告、调用记录和指标
```

清单准备阶段仅使用提交清单工具，不执行其他工具。执行子图到达 `$end` 后，内核继续检查；配置不能跳过这个阶段。模型未按协议提交清单、响应截断或发生错误时，本次 Run 失败，目标保留继续入口。

文件清单必须非空，路径相对于主工作区，拒绝越界、受保护状态路径、重复路径和符号链接。检查只确认普通文件存在，不要求非空，不检查语义或内容质量。检查异常与文件缺失分别处理。

纯问答模式由用户确认纳入本版：交付清单标记 `response`，报告为 `not_applicable`。空文件清单不能用于文件交付模式。

## 2. 四层对象与状态

| 对象    | 内容                                                   | 状态                                                                                |
| ------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Session | 会话身份、消息及目标集合                               | Schema 预留 open / closed / archived，当前入口使用 open                             |
| Task    | 用户目标、目标版本、清单、计划、Run 和产物关联         | ready / active / waiting / paused / completed / failed / cancelled                  |
| Run     | 本次输入、工作流快照、独立业务 State、游标、报告与指标 | queued / running / waiting / paused / interrupted / completed / failed / cancelled  |
| NodeRun | 一次节点进入的输入、输出、提交版本、尝试、错误和指标   | pending / running / waiting / paused / interrupted / completed / failed / cancelled |

当前使用串行调度，不提供队列服务、并行汇合或 Session 归档命令；相关枚举为模型预留。一次宿主执行一个 Run，同一 Task 保留一个未结束 Run。

Run 阶段为 preparing → executing → verifying → finalizing → finalized。缺文件会从 verifying 返回 executing，沿同一个 Run 继续；每次重新进入节点创建新 NodeRun。确认恢复中断节点时，沿用 NodeRun 身份并添加 Attempt。

普通消息在目标完成后建立新 Task；未完成的目标继续使用当前选择。使用显式命令可以控制归属，避免把不同目标混在一起：

```text
/task list
/task new 生成 README.md 与 design.txt
/task select <任务ID>
/task continue <任务ID> 补充部署说明
/task cancel <任务ID>
```

已有目标增加要求会保存旧目标文本，形成新目标版本，并重新准备清单和计划。暂停期间增加要求会结束原暂停 Run，并为修订后的目标创建新 Run；中断状态仍要求明确恢复确认。人工输入节点等待时，普通回复用于回答该请求。

## 3. 工作流配置

在主工作区创建 `.mini-agent/workflows.json`，内容为工作流数组，启动时加载。也可以通过 `workflows.register` 动态注册；修改已有定义必须增加 version，已有 Task/Run 继续保留自己的定义快照。

```json
[
  {
    "schemaVersion": 1,
    "id": "document",
    "version": 1,
    "name": "先整理结构，再执行交付",
    "entry": "outline",
    "nodes": [
      {
        "id": "outline",
        "type": "model",
        "inputs": {
          "goal": { "from": "task.goal" }
        },
        "config": {
          "instructions": "根据任务目标整理简洁的文档结构，输出大纲。"
        },
        "outputs": {
          "text": { "to": "state.outline" }
        }
      },
      {
        "id": "write",
        "type": "agent",
        "inputs": {
          "outline": { "from": "state.outline" }
        },
        "config": {
          "instructions": "参考输入大纲，完成用户目标，并生成生效清单要求的文件。"
        },
        "outputs": {
          "text": { "to": "state.answer" }
        }
      }
    ],
    "edges": [
      { "from": "outline", "to": "write" },
      { "from": "write", "to": "$end" }
    ]
  }
]
```

重启后选择：

```text
/workflow
/workflow document
/task new 生成项目 README.md
```

`/workflow` 的选择作用于新 Task。默认工作流 `general` 包含一个 Agent 节点。

### 节点类型

| type  | config                      | 输出字段                                    |
| ----- | --------------------------- | ------------------------------------------- |
| agent | instructions、可选 toolRefs | text；节点内部可多次调用模型和工具          |
| model | instructions                | text；一次模型请求，不开放工具              |
| tool  | toolRef                     | text、value；输入绑定得到的对象作为工具参数 |
| human | prompt                      | text、value；等待用户或 API 提交回复        |

宿主工具必须已注册；toolRefs 缩小 Agent 节点可见工具，不授予额外权限。工具执行仍经过宿主策略、参数校验和授权。

输入支持 `{ "from": "state.outline" }` 或 `{ "value": "固定值" }`。可读视图包含 task、state、input、feedback、output；其中 output 用于选择后继边。`task.goal` 是目标文本，`task.deliverables` 是路径数组。持久化对象中的业务数据位于 `run.state.data`。

输出只能写 `state.*`。缺失输入、缺失输出和字段冲突会报错；不能写生命周期、权限、清单或验收结论。路径解析禁止原型属性，不执行 JavaScript。

### 条件分支与循环

每个节点必须有一条无条件后备边，可另加条件边。先按配置顺序选择第一条满足条件的边，否则走后备边；本版一次选择一个后继。

```json
{
  "from": "review",
  "to": "revise",
  "when": {
    "from": "state.needsRevision",
    "op": "eq",
    "value": true
  }
}
```

支持 eq、ne、exists、truthy。连回已有节点形成循环；没有固定默认模型交流次数或图迭代次数上限，用户可取消。引用节点必须存在，所有节点必须从入口可达。

## 4. 计划确认、暂停与恢复

设置 `AGENT_CONFIRM_PLAN=1`，准备清单后等待计划确认：

```text
/task approve
/task reject
```

Agent 可以通过内核提供的 `task_plan_update` 更新已有计划步骤的进度，无需在 toolRefs 中列出该工具；不能修改清单或已确认计划内容。模型请求读取当前相关步骤的受预算约束视图，完整计划保留在 Task 与对应 Run 快照中。计划确认不会替代工具授权。

TUI 执行中按 **Ctrl+P** 请求在节点边界暂停；Ctrl+C 取消当前 Run。暂停不会中断正在执行的工具或模型请求，当前节点完成后停止推进。

```text
/task resume
/task recover
```

resume 用于正常暂停。recover 明确确认重新启动中断节点，可能重做该节点内已经发生的文件写入、命令或外部请求；运行时不会自动回滚或保证这些动作只发生一次。恢复前应检查原执行记录和实际环境。

人工输入节点或检查异常处于 waiting，使用普通输入回答，或者通过 waits.respond 回复，再调用 runs.resume。等待请求保留 ID，已结束请求不能重复回复。

## 5. 上下文与记忆策略

查看有效设置：

```text
/context
```

修改并保存到项目 `.mini-agent/settings.json`：

```text
/context {"summarize":true,"compactThreshold":0.8}
/context {"maxInputTokens":131072,"reservedOutputTokens":8192}
/context {"applyMemory":false,"generateMemory":false}
/context {"showWarnings":true,"warnThreshold":0.9,"overflowBehavior":"error"}
```

字段包括 maxInputTokens、reservedOutputTokens、recentTurns、maxToolResultTokens、maxMemoryTokens、memoryLimit、summarize、compactThreshold、safetyMargin、applyMemory、generateMemory、warnThreshold、showWarnings、overflowBehavior。

- 默认总窗口 131072 Token，输出预留 8192 Token，另计工具定义与安全余量。
- summarize 控制模型摘要；overflowBehavior=trim 时允许移除旧完整轮次以控制预算，error 时超限直接报错。
- applyMemory 控制自动召回及模型的记忆读取工具；用户仍可以使用 `/memories` 查看。
- generateMemory 控制模型通过 memory_save/memory_update 写入记忆的能力，不承诺每轮自动提取记忆；写入仍经过授权。
- showWarnings 只控制接近上限提示，不取消预算边界检查。
- 当前宿主与项目配置共用一套策略；运行期间不能修改。恢复时记录当段实际使用的配置。
- 项目设置覆盖全局设置。窗口和输出预留优先使用项目/全局 Settings 中的值，否则使用启动配置；summarize 与 compactThreshold 的显式启动配置优先。

用量以提供方返回或标注的估算为依据，未知用量的模型调用在 operation.details 中标记 unknown。Run 指标包含准备清单的模型与工具调用；消息底部用量来自对应 Agent 执行回复。/stats 汇总当前会话已保存 Run 和运行中增量，重启后保留已有统计。lastRunMs 汇总本 Run 各次推进的耗时，包含执行中的授权等待，不包含两次恢复之间的离线停留。

## 6. 自定义工具

支持两种方式：

1. 宿主通过 RuntimeDependencies.tools 注册新的 RegisteredTool，实现参数校验、执行与证据接口。
2. 用户在 `.mini-agent/tools.json` 配置已有内置、宿主或 MCP 工具的别名与固定参数。

```json
[
  {
    "name": "project_readme",
    "description": "读取主工作区的 README.md",
    "target": "read_file",
    "fixed": { "path": "README.md" },
    "parameters": {
      "type": "object",
      "properties": {},
      "additionalProperties": false
    }
  }
]
```

配置启动时加载。输入参数 Schema 支持 object、string、number、integer、boolean、array，以及 properties、required、additionalProperties、items、字符串 enum。未支持的 Schema 关键字报错。submit_delivery_checklist 与 task_plan_update 为内核保留名称。

固定参数覆盖调用参数；目标工具继续执行自己的校验与权限检查。命令或 MCP 别名仍需目标工具要求的授权，记忆别名也遵守上下文策略。配置文件不执行任意代码；新实现由宿主注册或通过 MCP 接入。

## 7. 客户端协议

现有 AgentClient 保留 initialize、subscribe、dispatch、close。快照包含 protocolVersion=2 和 execution，execution 事件带 generationId、状态修订序号及四层身份；其他运行时事件携带 scope，便于客户端归属消息与调用。重置会话产生新 generationId，客户端以会话、generationId 和修订号一起识别状态版本。

| 命令组 | 命令                                                                 |
| ------ | -------------------------------------------------------------------- |
| 目标   | tasks.list、tasks.create、tasks.select、tasks.continue、tasks.cancel |
| 执行   | runs.get、runs.pause、runs.resume                                    |
| 等待   | waits.respond                                                        |
| 查询   | execution.get、runtime.capabilities、tools.describe                  |
| 工作流 | workflows.list、workflows.register、workflows.select                 |
| 策略   | context.get、context.configure                                       |
| 兼容   | tasks.run、tasks.current、run，以及既有会话、模型和工具接口          |

```ts
const task = await client.dispatch({
  type: 'tasks.create',
  input: '生成 README.md 和 design.txt',
  workflowId: 'document',
});

await client.dispatch({ type: 'tasks.continue', id: task.id });
const execution = await client.dispatch({ type: 'execution.get' });
console.log(execution.runs, execution.nodes, execution.reports);
```

HTTP 继续使用 GET /api/state、GET /api/events、POST /api/commands，两个传输入口均执行相同命令校验。runtime.capabilities 如实报告串行执行、节点边界恢复、应用层隔离和不支持事件重放。

兼容 TaskResult 是一次接口返回视图，可以返回 waiting 或 paused；没有 finishedAt 表示 Run 尚未结束。真正目标状态位于 execution.tasks，执行状态位于 execution.runs。旧 run 字符串接口仅在完成时返回摘要，否则拒绝 Promise。

## 8. 持久化、兼容与边界

- `.mini-agent/executions/<session>.json` 是当前会话的权威执行清单，原子保存目标、Run、NodeRun、等待、报告、产物登记、调用记录和规范历史。
- 在节点启动前、输出提交后和外层阶段边界保存；持久化输出与游标后才推进。人工等待、计划确认与边界暂停可跨进程保存。
- `.mini-agent/sessions/` 与 `.mini-agent/tasks/` 保留旧接口兼容数据。读取 V1.1 最后结果时不虚构 Task、清单或检查点。
- 客户端查询读取最近成功保存的执行清单，完成状态在主记录提交后发布；旧接口缓存写入失败单独提示，不将已保存的目标结果改为失败。
- 重置、删除会话会同步处理 executions；迁移包包含新执行状态和配置，但不包含项目交付文件本身。
- Run 保留使用过的工作流、清单、计划快照与报告；新 Run 从独立业务 State 开始，文件系统仍由同一工作区共享。
- 产物当前登记路径、大小和来源，不提供不可变文件内容快照；报告表示检查时刻的观察结果。
- 一个会话文件由一个宿主进程负责写入。HTTP 多客户端共享该宿主；没有多进程写入协调或分布式锁。
- 当前保留最新推进位置，不提供历史检查点回放、并行汇合、子工作流执行器、自动技术重试或完整操作系统沙箱。完整候选结构中的对应扩展继续保留在设计文档。
- 客户端重连通过快照恢复已保存状态，流式片段不持久重放。客户端 close 与宿主 close 含义不同；TUI 拥有本地宿主，退出会取消正在运行的调用。

## 9. 模块化与学习入口

模型、Agent 循环、上下文、权限、记忆、任务存储、工作流目录和验收器可以在宿主通过工厂注入。`config.executor` 可为 agent/model/tool 节点选择已注册的命名执行器；human 的持久等待由内核管理。工厂在上下文配置更新和会话切换时继续生效。

依次阅读：

1. `src/core/model/types.ts` 与 `src/core/agent.ts`：模型与自主执行。
2. `src/core/workflow/definition.ts` 与 `src/core/execution/types.ts`：图和四层对象。
3. `src/app/ports.ts`、`src/app/tasks/runner.ts`、`src/app/execution/engine.ts`：执行依赖与固定阶段。
4. `src/app/nodes/`：节点执行器和注册目录。
5. `src/host/dependencies.ts`、`src/host/services.ts`：默认实现与工厂装配。
6. `src/protocol/index.ts`、`src/ui/`：独立客户端类型与终端展示。

完整扩展代码见 [模块开发指南](./module-development.md)，模块职责见 [架构指南](../ARCHITECTURE.md)，版本计划见 [技术规划](./technical-roadmap.md)。自动化与真实环境验证分别记录在 CHANGELOG。

# V1.2 设计基线与实现范围

设计方向确认：2026-10-23。模块化整理：2026-10-25。当前为 1.2.0 开发代码，尚未据此声明正式发布。

## 版本目标

建立可配置、可观察、可恢复的通用 Agent 基础。用户目标与单次执行分开，领域能力通过工作流与工具表达；多个 UI 使用同一命令和事件协议。

## 不变的完成规则

正常完成必须经过内核完整性阶段。文件清单不能为空，检查器必须覆盖清单全部文件；内核校验报告归属并根据每项观察计算状态。缺失文件继续同一 Run，重新进入执行子图。检查异常进入等待或失败，不能伪装成通过。

纯回复可以完成，文件检查明确不适用。实际命令检查和文件完整性分别展示。暂停、取消、异常结束不虚构已经验收。

## 扩展生效规则

模块工厂和执行器在宿主启动时注册。配置文件只能引用已注册能力。工作流更新需增加版本，Run 保留原配置快照；运行中不热替换实现。上下文可在空闲时重新配置，继续使用所选工厂。

模块扩展不获得修改任务生命周期的客户端权限。宿主 JS 属于受信任代码；文件范围和工具授权仍不是操作系统沙箱。

## 兼容与迁移

- 公开客户端命令继续兼容 `run`、`tasks.run`、`tasks.current` 等既有入口。
- `TaskResult` 是单次接口返回的结果投影，目标状态以 execution.tasks 为准。
- V1.1 消息和最后结果可读取，不构造不存在的目标、清单或检查点。
- 内部源码路径已重组。扩展应优先从 `src/index.ts` 或 `src/client.ts` 导入，避免绑定内部目录。
- 默认数据目录和 JSON 权威记录结构保持；新增 `config.executor` 是可选字段。

## 当前边界

串行执行、单宿主写一个会话文件、节点边界保存。恢复中断节点可能重复外部操作；无历史回放、分布式锁、并行汇合、子图和系统沙箱。产物不保存不可变内容版本。事件重连使用快照，无持久事件重放。

当前模块化是可替换接口和启动装配，不包含包市场、依赖安装或运行中热卸载。全局/项目元数据仍由默认 Node 宿主保存在本地。

## 发布前检查

类型、脚本语法、依赖边界、格式及自动化回归应全部通过；在线提供方、实际终端、崩溃恢复与迁移还需按使用环境验收。当前已执行的检查记录见 CHANGELOG，不将设计确认等同于发布完成。

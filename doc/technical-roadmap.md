# Mini Agent 技术规划

更新时间：2026-10-25。当前代码版本：V1.2.0 开发版。V1.2 的通用 Agent 方向已确认；后续版本分配是建议顺序，不表示已经实现或承诺发布日期。

本文是当前技术规划入口。配置以 [V1.2 指南](./v1.2-usage.md) 为准，模块接口以 [模块开发指南](./module-development.md) 与代码为准；早期专题中的完整候选字段保留作设计参考。

## 1. 产品与内核边界

产品面向通用任务。编码能力是工作流、工具和权限的组合；其他领域无需复制 Agent 内核。TUI、Web、桌面和 App 共享命令与事件协议，各自实现交互和展示。

内核必须保留的规则：

1. Session → Task → Run → NodeRun 四层身份；Task 跨轮持续，Run 表示一次推进。
2. 固定外层流程：输入和清单准备 → 自定义执行子图 → 完整性检查 → 结果。
3. 文件任务提交非空清单，缺失项返回执行；纯回复允许结果文本，报告标明不适用。
4. 计划属于 Task，执行时按预算投影；确认计划不会自动授予工具权限。
5. 业务 State、调度状态、调用记录和 UI 状态分别保存。
6. 模型循环持续到正常完成；取消、异常和预算策略保留独立出口。

## 2. 软件分层与依赖约束

| 层                       | 职责                                     | 可依赖的项目层      |
| ------------------------ | ---------------------------------------- | ------------------- |
| core                     | 领域对象、协议、规则、能力接口与默认算法 | core                |
| protocol                 | 客户端 JSON 命令、快照、事件与校验       | protocol、core      |
| app                      | 目标生命周期、图调度、节点动作、结果提交 | app、core、protocol |
| infra / tools / adapters | 文件、进程、网络、工具和传输实现         | 核心接口及必要实现  |
| host                     | Node 运行环境、默认装配、会话与配置命令  | 应用与具体实现      |
| ui                       | 输入、布局、交互、展示投影               | ui、protocol        |

启动文件负责连接宿主和客户端。库入口 `src/index.ts` 不创建 UI；`src/client.ts` 导出仅使用 fetch/流的远端客户端。当前宿主仍是 Node 应用，浏览器使用远端客户端接入。

## 4. 模块化落地原则

### 4.1 接口由使用方定义

执行器只依赖需要的能力。文件存储、模型厂商和终端组件放在外层。默认实现通过 `RuntimeDependencies` 注入，不在 TaskRunner 或 ExecutionEngine 内 `new` 文件服务。

### 4.2 配置与可执行代码分开

用户 JSON 描述工作流、条件、数据绑定和已有工具的参数。宿主注册 TypeScript 执行器或模块，配置只能按名称引用。配置不执行 JavaScript，不动态导入用户给定的代码路径。

### 4.3 模块有明确生效时间

工厂、工具组、命名执行器、宿主模块在启动时装配。工作流可以通过接口注册版本；上下文配置可在空闲时更新并重新创建策略实例。进行中的 Run 不热替换实现。

模块按安装逆序清理；安装失败会释放已安装模块，正常关闭先等待执行和状态保存结束再清理资源。

### 4.4 强制阶段由内核保留

节点插件只负责一次执行输出，内核负责 Attempt、状态提交、路由与验收。文件检查插件报告观察，内核核对任务/Run/清单版本和每个文件项，并据观察重新计算完整性状态。

宿主代码本身是受信任代码。任意 JS 仍可访问进程能力；需要强隔离时，应使用独立执行环境。

## 5. 版本路线

### V1.2：通用运行基础与模块边界（当前）

已具备通用工作流、四层对象、完整性闭环、配置接口、模块注入和独立客户端协议。当前重构继续归入 V1.2，不因移动目录另开大版本。

发布前验收重点：

- 默认流程与自定义流程均经过同一完整性阶段。
- 更换上下文、记忆、存储、权限或节点执行器后，TUI 和 HTTP 无需改代码。
- 会话切换、配置更新、取消和初始化失败正确管理模块生命周期。
- 旧消息与结果可读取；新状态使用权威执行清单。
- 类型、依赖边界、格式、自动化回归通过，并完成真实模型与真实终端验收。

### V1.3：运行可靠性与可观测（建议）

重点是“可解释地恢复和定位问题”：统一重试/超时/预算，操作幂等标识与恢复确认，检查点版本迁移，事件持久化、重连补发、日志保留与脱敏。完善当前暂停和恢复保证后，再扩大并行能力。

### V1.4：扩展生态与知识能力（建议）

补齐工具和 Skills 的描述、版本、配置校验、装卸与调试；增强 MCP 连接生命周期；引入异步检索端口，支持文档导入、切块、检索和来源引用的基础 RAG。已有简单记忆继续可用，RAG 作为可选模块。

远程 RAG 不应硬塞进当前同步 MemoryPort；先定义异步查询、取消和预算接口，再接向量库或远程服务。

### V2：高级工作流与强执行隔离（建议）

在兼容策略明确后，引入子工作流、并行分支与汇合、受控多 Agent 节点，以及独立进程/容器沙箱和资源配额。需要定义状态合并、并发文件冲突、权限交集与外部副作用恢复。编码模板只是其中一类工作流。

操作系统沙箱若成为近期刚需，应提前实施独立执行器，不必等待 V2 发布。

### V3：多用户服务与协作（候选）

多租户身份、任务队列、分布式存储、跨机器调度、协作客户端和运维体系。是否需要这一阶段由实际使用需求决定；当前桌面/本地通用 Agent 不为此预先引入复杂基础设施。

模型语义验收、评分置信度和自动质量评审需要独立评价集与错误成本设计，不与文件完整性混用，暂不承诺版本。

## 6. 当前限制与取舍

- 调度串行，一个宿主一次推进一个 Run；不同任务仍可保存等待状态。
- 一个会话的执行文件只允许一个宿主写入；不具备多进程锁。
- 节点边界保存，不恢复 JS 函数栈；恢复可能重复外部动作。
- 产物只登记路径、大小和来源；没有不可变内容版本。
- 会话索引、密钥、项目设置、兼容 Todo、调用日志与长输出仍由默认 Node 宿主使用本地文件管理；相关代码已归位，但未为每项提供顶层工厂。
- 记忆端口目前同步检索，不是完整 RAG。
- 观察器为同步通知，不提供持久事件重放；重连使用快照。
- 模块注入是启动装配，尚无运行中热加载、包依赖解析或插件签名机制。

这些限制应体现在 `runtime.capabilities` 和文档中。未来扩展不能悄悄改变完成、权限或恢复语义。

## 7. 开发完成标准

每个版本同时交付实现、配置示例、迁移说明与针对行为的回归验证。依赖检查防止核心反向依赖 UI/存储；集成检查证明默认实现和注入实现经过相同内核路径。对未验证的在线模型、终端环境和外部系统明确记录，不把通过类型检查视为线上保证。
